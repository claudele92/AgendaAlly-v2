## What prevents replay here

The restore is physically quarantined. Fourteen actual MySQL DML probes—seven
each as the runtime identity and root—must fail with native error **1290**:
generic late callback, MTN callback, funding, refund, payout, email-send state
change, and replacement request identity. These are database write probes, not
native callback/service/HTTP invocations. Providers, SMTP, workers and routes
are never started; database quarantine alone would not prevent an external send
by an independently launched process. Do not start one.

All selected-point rows, full ledger, native metadata/guards and grants must
match before these probes. The restored uncertain rows remain exactly as backed
up, with no state normalization, replacement intent, terminal update, deleted
reservation, changed money, grant or authentication record. Full restored/final
snapshots must match. Authentication invalidation is separately qualified in the
earlier rehearsal; this campaign leaves the entire restore unchanged and unserved.

The passive reconciliation policy always returns **HOLD**:

- Without independent evidence: `INDEPENDENT_EVIDENCE_MISSING`.
- Forged signature, wrong lineage/identity/amount/currency/scale, stale or
  malformed time/outcome, and conflicting outcome/reference: explicit rejection.
- Valid retained observations: record the observed outcome for owner
  reconciliation, suppress automatic action and retain quarantine.
- Duplicate identical observations do not create another effect.

Local database absence or PENDING/UNKNOWN is **not proof of external failure**
and cannot authorize re-dispatch, another funding event, refund, payout or
email resend. Reconciliation joins the existing immutable identity to retained
evidence; it does not generate a new intent or infer terminal evidence from an
older backup. Even valid mock evidence grants no writeback/release authority.
Actual trusted external evidence and a separately reviewed owner-approved
reconciliation/traffic-switch procedure remain required for real recovery.
