==================================================
6. FINANCIAL SEMANTICS AUDIT
==================================================

The Customer mobile app MUST preserve the accepted AgendaAlly financial distinctions.

Audit all mobile:

- labels;
- models;
- state mappings;
- buttons;
- notifications;
- API handling;
- optimistic state;
- local persistence

against these rules:

CANCELLED != REFUNDED

REFUND REQUESTED != REFUNDED

REFUND APPROVED != REFUNDED

APPROVED != MONEY MOVED

PAYMENT SELECTED != PAYMENT COLLECTED

CASH SELECTED != CASH COLLECTED

REQUIRES_REVIEW != COMPLETED

Only authoritative COMPLETED financial state may be represented as completed refund execution.

The mobile app must not infer financial completion merely from:

- booking cancellation;
- approval;
- request submission;
- Cash selection;
- provider redirect;
- optimistic local state;
- stale cached state.

Check whether the app currently uses ambiguous labels such as:

- Paid
- Refunded
- Completed
- Successful

where the backend does not establish that financial state.

Flag every mismatch.

7. REFUND & CANCELLATION MOBILE AUDIT
==================================================

Compare the mobile cancellation/refund experience against the final backend and current Refund & Cancellation Policy model.

The intended conceptual sequence is:

BOOKING CANCELLATION
→ REFUND ELIGIBILITY
→ REFUND REQUEST
→ REVIEW / APPROVAL
→ FINANCIAL COMPLETION

These are distinct concepts.

Audit whether the app incorrectly collapses them.

The mobile app must not independently invent:

- refund percentages;
- cancellation fees;
- refund windows;
- refund amount;
- processing timelines.

The backend-authoritative eligible amount and policy should control the Customer experience.

Verify whether the app can represent:

- no refund eligibility;
- eligible refund;
- requested;
- approved but not completed;
- rejected;
- cancelled request where applicable;
- requires review;
- completed.

Do not implement missing states yet.
