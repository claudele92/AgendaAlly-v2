# 5. Logo visual-size strategy

Do not use one fixed pixel dimension everywhere.

Create/reuse sensible presentation variants such as conceptually:

- header
- auth
- footer
- invoice

These should remain presentation variants of ONE branding system, not separate branding configurations.

For example, a shared component may conceptually support:

Exact implementation is up to the existing architecture.

Avoid unnecessary abstraction if the existing shared logo component already supports this cleanly.

The important requirement is consistent visual sizing.

# 6. Account for transparent padding inside logo assets

Inspect the supplied/configured images themselves.

If the image canvas contains substantial transparent margins that cause the visible logo to appear much smaller than its CSS box, do not compensate everywhere with arbitrary huge CSS dimensions.

Choose the cleanest safe solution.

Possible solutions include:

- using an existing tightly bounded approved asset;
- producing an application-owned optimized derivative of the SAME approved artwork with transparent empty margins removed;
- adjusting the image presentation/container when that is sufficient.

Do NOT alter:

- symbol geometry;
- colors;
- typography;
- proportions;
- artwork;
- brand identity.

Removing purely empty transparent canvas space is acceptable if necessary for technical presentation.

Do not overwrite the original uploaded Admin branding asset merely to solve rendering.

If an optimized derivative is generated, it must remain derived from the configured asset and must not create a competing branding configuration.
