AgendaAlly — Customer Footer Headless UI Hydration Mismatch

A second Customer hydration issue has been found.

This is NOT the previously fixed Shop-hours/timezone issue.

The mismatch occurs in the shared Customer Footer under:

app/(store)/(booking)/(with-footer)/layout.tsx

at:

<Footer settings={parsedSettings} />

React reports that the server and client generated different Headless UI
Disclosure IDs.

Examples:

SERVER/CLIENT DIFFERENCES

headlessui-disclosure-button-_R_kqitqbnabmaqlb_
vs
headlessui-disclosure-button-_R_2jabn9et9epbalb_

and corresponding:

headlessui-disclosure-panel-...

The affected Footer groups include at least:

- Discover
- Your Account
- Information

============================================================
1. DIAGNOSE BEFORE FIXING
============================================================

Trace the complete Footer render tree and determine WHY React's deterministic
ID sequence differs between SSR and the client's first render.

Audit:

- Footer component;
- FooterGroup;
- Headless UI Disclosure;
- all conditional Footer children;
- authentication-dependent rendering;
- settings-dependent rendering;
- locale-dependent rendering;
- responsive rendering;
- browser-only branches;
- dynamic imports;
- Suspense boundaries;
- client-only providers;
- components rendered before/beside Footer whose server/client tree may differ.

Search specifically for:

typeof window !== "undefined"

window.*

document.*

localStorage

sessionStorage

matchMedia

useMediaQuery

screen width

navigator

Date.now()

Math.random()

useId()

conditional hooks/components

authentication state that differs between SSR and hydration

settings loaded differently server/client.

============================================================
2. DO NOT ASSUME HEADLESS UI ITSELF IS THE BUG
============================================================

The mismatched generated IDs are likely a symptom of server/client render-tree
divergence.

Do NOT immediately:

- replace Headless UI;
- hard-code its generated IDs;
- remove accessibility IDs;
- strip aria relationships;
- suppress the hydration warning.

First determine why the server and client's React ID allocation differ.

Headless UI Disclosure must retain correct accessibility behavior.

============================================================
3. INSPECT FOOTERGROUP
============================================================

Trace the exact implementation of:

FooterGroup

and its use of:

<Disclosure defaultOpen={true}>

Determine whether the Disclosure is actually necessary at every breakpoint.

If Footer groups are intended to be:

and first client render structurally different.

Prefer CSS for purely visual responsive behavior.

Do not infer this is the cause without tracing it.
